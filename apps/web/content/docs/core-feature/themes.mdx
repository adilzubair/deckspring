A theme is a **bundle of two paired files** under `themes/`:

- `themes/<id>.md` — agent-facing recipe: palette, typography, layout,
  fixed components, motion. `create-slide` reads this before authoring.
- `themes/<id>.demo.tsx` — a runnable mini-slide that demonstrates the
  theme. The dev UI's **Themes** panel imports it and renders it as the
  theme's live preview card.

Both files share the same stem so the runtime can pair them automatically.
If you author more than two decks you'll want them to look related — a theme
captures the recipe in one place any deck can reference, and the demo makes
it browsable in the dev UI before you pick one.

## Create and manage themes in Studio

In the local Studio, open **Themes** and choose **Create theme**. You can describe a new visual direction or extract one from an existing deck. Studio asks the selected model for validated theme data, never executable code, and opens an editor for identity, palette, typography, composition, motif, spacing, corner style, and motion. A trusted three-page preview updates as you edit.

Saving writes the markdown and demo as a pair. Saved themes support edit, duplicate, preview repair, and delete actions, and appear beside the built-in quick styles when generating a deck. Theme IDs become filenames and stay immutable after saving. Deleting a referenced theme detaches its metadata link from affected decks without rewriting their visual source.

Existing free-form theme recipes remain browseable. Choose **Import into Studio** on one to convert it to the validated Studio format while preserving its visual direction.

## File layout

```text
themes/
├── corporate.md
├── corporate.demo.tsx
├── editorial.md
├── editorial.demo.tsx
├── retro-print.md
└── retro-print.demo.tsx
```

Framework themes may use free-form markdown. Studio themes add validated machine-readable frontmatter while preserving the canonical readable recipe. A minimal framework template:

```md title="themes/corporate.md"
---
name: Corporate
description: Calm corporate look with a single accent.
mode: dark
---

# Corporate

## Palette
- ink: #0a0a0c
- accent: #4a52b5
- mint: #1f8458

## Typography
- display: 'Söhne', system-ui
- mono: 'JetBrains Mono'

## Voice
- Tight, declarative, never coy.
- One concept per slide.
```

The demo is a normal slide module — same shape as `slides/<id>/index.tsx`,
just placed under `themes/` so the runtime treats it as preview-only (it
does not appear in the slides list):

```tsx title="themes/corporate.demo.tsx"
import type { Page } from '@deckspring/core';

const Cover: Page = () => (/* …inline Title / Footer using theme tokens… */);
const Content: Page = () => (/* … */);

export default [Cover, Content];
```

Keep the demo's inline Title/Footer/Eyebrow components verbatim in sync
with the snippets in the markdown — what authors see in the Themes panel
should match what `create-slide` will paste into a real slide.

## Using a theme

In Studio, select the saved theme from **Visual style** before choosing **Generate deck**. Studio applies its palette, typography, composition, motif, spacing, corners, and motion and records the theme ID in deck metadata.

Outside Studio, the optional agent workflow can still mention a theme by name:

```text
/create-slide for "Q3 board update — use the corporate theme"
```

The agent loads `themes/corporate.md`, applies the palette and type stack,
and writes pages that match.

## Extracting a theme

Already have a deck whose look you like? In Studio, choose **Create theme**, then **Extract from deck**. Framework users can optionally use [`/create-theme`](/docs/skills/create-theme) to author the paired files with an agent.
